# 歌曲语言学习软件：首版设计与环境检查

日期：2026-10-19

## 目标与范围
Flutter + Dart 客户端，本地优先，面向 Android、iOS、Windows、macOS 和 Web。首版用于边学边开发，包含歌曲导入页面框架、LRC/TXT 歌词解析、示例歌曲逐句练习、上一句/下一句和练习进度。不将演示计时器描述为真实音频播放。纯音频歌词提取留给后续独立 Python + FastAPI 服务。

## 方案选择
推荐单个 Flutter 应用、按功能分目录，使用 Flutter 自带状态机制，避免学习初期引入复杂依赖。备选方案为一开始采用多包仓库及完整状态管理框架；可扩展性更强，但增加初期学习负担。另一方案为先仅写 Web 原型；启动更快，但无法直接验证原生客户端组织方式。

## 项目结构
- client/：标准 Flutter 工程，保留五个平台入口。
- client/lib/app/：主题及应用入口。
- client/lib/features/library/：歌曲与歌词导入界面。
- client/lib/features/practice/：逐句练习界面与进度。
- client/lib/domain/：歌曲、歌词行和纯 Dart 解析器。
- client/test/：LRC/TXT 解析与练习界面测试。
- docs/：运行、学习路线与架构说明。
- services/audio/README.md：后期服务边界说明，首版不要求 Python。
- scripts/：诊断与运行入口；SDK 不提交到 Git。

## 数据和错误处理
首版示例存于应用资源，用户选择歌词后在本地解析。LRC 支持时间戳和多时间戳；TXT 按非空行生成无时间轴歌词。空文件、格式错误、文件读取失败给出可理解提示。Web 不使用 dart:io 文件路径；跨平台导入采用平台兼容文件选择接口。首版不承诺跨重启持久化或完整歌曲播放，后续再引入本地数据库、音频文件存储和播放器。

## 验收与阶段
1. 确认或安装 Flutter stable（附带 Dart），优先复用 VS Code 与已有插件。
2. 创建工程、文档、Git、测试。
3. 执行 flutter doctor -v、flutter pub get、flutter analyze、flutter test、flutter build web，并实际启动 Web 验证页面。
4. 依工具情况验证 Windows；Android 需 Android SDK/JDK 及设备或模拟器；iOS/macOS 构建需要 Mac/Xcode。
5. 后续顺序：真实播放和逐句循环 → 本地持久化 → 录音跟读 → 独立服务自动转写及对齐。
